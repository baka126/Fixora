# Dashboard UI

The Fixora Dashboard provides a centralized view of your cluster's health, ongoing investigations, and remediation history.

## Accessing the Dashboard

By default, the dashboard is accessible via the Fixora Service. If you are using the Helm chart, you can enable an Ingress:

```yaml
ingress:
  enabled: true
  hosts:
    - host: fixora.example.com
      paths:
        - path: /
          pathType: ImplementationSpecific
```

## Features

### 1. Alert Triage
The main view shows firing alerts from Alertmanager. 
- **Auto-Investigate:** Fixora automatically begins analysis for critical alerts.
- **Manual Trigger:** For lower-priority alerts, you can click "Investigate" to start the forensic process.

### 2. Investigation Details
Each investigation page displays the **Evidence Chain**:
- **Metric Proof:** Visualizations of CPU/Memory/Error trends.
- **Dependency Graph:** Shows related resources (Services, ConfigMaps, Secrets).
- **Log Summary:** AI-powered plain-English explanation of the error.
- **FinOps Impact:** Monthly cost implications and Cost of Downtime (CoD).

### 3. Remediation Center
Track all GitOps Pull Requests generated by Fixora.
- **Status Tracking:** See if a PR is open, merged, or failed validation.
- **Dry-Run Results:** View the `kubectl diff` or `helm template` output for proposed fixes.

### 4. User & Group Management
Administer access to Fixora using role-based access control (RBAC).
- **Roles:** `Admin`, `Operator`, `Viewer`.
- **Groups:** Organize users for notification targeting.

---

## Security
Access to the dashboard is protected by JWT authentication. The first user to access the dashboard will be prompted to set up the administrator account.
